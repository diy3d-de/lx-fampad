Home Assistant → Familyhub: Zählerwerte automatisch eintragen

Konzept mit API-Entwurf, Home-Assistant-Seite und Mockups · Stand 26.10.2026 · Entwurf, noch nichts gebaut

Kurzfassung. Zählerdaten sind im Familyhub Ende-zu-Ende verschlüsselt: der Server kann sie nicht lesen (sie verraten, wann jemand zu Hause ist). Ein einfacher „Server nimmt Werte per Web-Aufruf an“ würde das aufweichen. Mein Vorschlag ist deshalb ein Briefkasten: Home Assistant wirft die Werte verschlüsselt beim Server ein (nur mit einem Einwurf-Schlüssel, der nichts lesen kann); die App eines Elternteils holt sie ab, prüft sie und schreibt sie wie einen von Hand eingetragenen Stand. Home Assistant braucht dafür eine kleine eigene Integration (Crypto lässt sich dort nicht per Standard-YAML erledigen).

1 · Ausgangslage und Ziel

  • Quellen in Home Assistant (HA): dein Stromzähler (Bezug, ggf. Einspeisung) und die Anker Solix Solarbank 3 E2700 (Solarerzeugung, Batterie laden/entladen). Das sind fortlaufende Zählerstände in kWh (total_increasing) – genau das, was die App als „Zählerstand“ kennt.
  • Ziel: je Tag ein Stand pro Kanal, automatisch, ohne dass du etwas tippst. Verbrauchskurve, Kosten und Solar-Ersparnis in der App rechnen dann wie bisher.
  • Nicht Ziel: Live-Leistung (Watt im Minutentakt). Das wäre eine andere Aufgabe (siehe Ausbau).

3 · Architektur (Weg C)

Schlüssel und Vertrauen

  • Briefkasten-Schlüsselpaar: erzeugt die App beim Einrichten. Der öffentliche Teil geht in den Kopplungscode, der private wird im verschlüsselten Zähler-Datensatz abgelegt – damit hat ihn jedes Elternteil automatisch, Kinder nie, der Server nie.
  • Einwurf-Token (fhi_…): vom Admin mit frischer Bestätigung erzeugt, einmal angezeigt, beim Server nur als Hash gespeichert. Darf ausschließlich einwerfen: nicht lesen, nicht synchronisieren, keine Anmeldung. Jederzeit widerrufbar.
  • Echtheit: Die Sealed Box allein beweist den Absender nicht. Darum steckt im Kopplungscode zusätzlich ein zufälliges Geheimnis; HA hängt an jedes Päckchen einen HMAC. Selbst wer das Token stiehlt (oder der Server-Betreiber) kann damit keine gefälschten Werte unterschieben.
  • Nach dem Abwurf kennt der Server nur: Zeitpunkt, Größe, Token. Keine Kanäle, keine Zahlen.

5 · Home-Assistant-Seite

Empfehlung: kleine eigene Integration („Familyhub“), per HACS installierbar. Gründe: sie braucht PyNaCl (libsodium) für die Sealed Box, einen lokalen Puffer bei Ausfall und eine Einrichtung per Oberfläche statt YAML. Ablauf:

  1. Integration hinzufügen → Kopplungscode aus der App einfügen (enthält Adresse, Token, öffentlichen Schlüssel, Geheimnis).
  2. Pro Kanal einen Sensor wählen (nur total_increasing-Sensoren in kWh werden angeboten).
  3. Die Integration merkt sich um 23:59 Uhr (Ortszeit) den Stand je Kanal, verschlüsselt, sendet. Schlägt es fehl: Puffer, Wiederholung mit Wartezeit, beim Start Nachholen. Ein Sensor „Familyhub: letzter Versand“ zeigt den Zustand.
  4. Fehlt ein Sensorwert (unavailable), wird nichts gesendet (kein „0“), die Lücke bleibt eine Lücke.

Vorläufer ohne HACS (zum schnellen Testen): ein Pyscript- oder AppDaemon-Skript mit denselben ~40 Zeilen. Reines rest_command reicht nicht, weil HA kein Sealed-Box-Verschlüsseln kann.

Kanäle als Vorschlag: strom_bezug, strom_einspeisung, solar_erzeugung, bank_geladen, bank_entladen. Welche Sensoren deine Solix-Anbindung liefert (z. B. die HACS-Integration „Anker Solix“), muss ich noch gegen deine echten Entitäten prüfen.

7 · Sicherheit und Datenschutz

  • Server und Sicherungen enthalten nur undurchsichtige Päckchen, die nach spätestens 30 Tagen verschwinden (und sofort nach dem Eintragen).
  • Token-Diebstahl: kann nur Müll einwerfen (begrenzt durch Rate-Limit), nichts lesen, nichts fälschen (HMAC), und wird per Widerruf sofort wertlos.
  • Server-Betreiber kann weder lesen noch glaubhaft fälschen. Er könnte Päckchen weglassen; die App zeigt Lücken ehrlich als Lücke.
  • Home Assistant selbst ist der schwächste Punkt (liegt bei dir zu Hause). Dort liegt Geheimnis + öffentlicher Schlüssel + Token, aber nie ein Schlüssel, der Familyhub-Daten lesen kann.
  • Kinder: sehen den Bereich nie, bekommen weder Kachel noch Briefkasten (gleiche Regel wie die Zähler).
  • Kein neuer Fremddienst, kein Cloud-Umweg über Anker oder HA-Cloud; HA sendet nur an deine Domain.

9 · Offene Punkte (brauche deine Antwort)

  1. Welche Entitäten hast du? Wie liest du den Stromzähler aus (Lesekopf, Shelly, Smart-Meter-Gateway …), und welche Sensoren liefert die Solix-Anbindung als Gesamtwerte in kWh? Eine Liste deiner sensor.*-Namen genügt.
  2. Takt: reicht ein Stand pro Tag (Vorschlag), oder willst du stündliche Werte für eine genauere Tageskurve?
  3. HA-Installation: Home Assistant OS/Supervised oder Container, und ist HACS vorhanden (sonst liefere ich die Integration als Ordner zum Hineinkopieren)?

Kleine Detailfrage für die Umsetzung (kein Blocker): Der Server akzeptiert Zähler-Stände heute nur mit zufälligen IDs. Bei zwei gleichzeitig abholenden Geräten kann deshalb ein Tag doppelt entstehen; die App führt das beim Lesen zusammen (wie bei den Monatswerten), das Löschen im Briefkasten ist atomar und verhindert es fast immer.
